Ara is an open-source vector processing unit developed by the [PULP Platform](https://pulp-platform.org/) at ETH Zurich and the University of Bologna. It operates as a coprocessor to the [CVA6](https://github.com/openhwgroup/cva6) scalar core and implements the **RISC-V Vector Extension v1.0 (RVV)** — the ratified standard for vector computation on RISC-V processors. Ara is designed to bring scalable, energy-efficient data-parallel acceleration to custom SoC designs, research prototypes, and FPGA platforms, with a fully open-source hardware implementation licensed under Solderpad 0.51.

## Architecture at a glance

Ara is structured as a collection of cooperating hardware units. The following describes each major component:

**Dispatcher** — Receives vector instructions from CVA6 over the accelerator interface. It decodes the instruction, reads scalar operands, and forwards the decoded operation to the sequencer.

**Sequencer** — Manages in-order issue of vector operations across the lanes. It resolves data hazards, tracks vector register file dependencies, and dispatches micro-operations to each lane and to the shared functional units.

**Vector lanes** — The main compute fabric. Each lane contains:
- A slice of the 32-entry vector register file (VRF)
- A SIMD integer ALU and multiplier
- A SIMD floating-point unit (FPU) with multi-precision support
- Operand requesters that stream register data to functional units

**Vector Load/Store Unit (VLSU)** — Handles all memory operations: unit-stride, strided, indexed, segment, and fault-only-first loads and stores. It interfaces with the AXI4 memory bus.

**Slide Unit (SLDU)** — Executes vector slide and inter-lane data movement operations, including `vslideup`, `vslidedown`, `vrgather`, and `vcompress`.

**Mask Unit (MASKU)** — Handles mask register operations, mask-logical instructions, population count (`vcpop.m`), first-set-bit (`vfirst.m`), and permutation support (`viota`, `vid`).

<Note>
  Ara's maximum supported element width is **ELEN = 64 bits**. Operations on elements wider than 64 bits are not supported. The number of lanes must be a **power of two** (2, 4, 8, or 16). VLEN must be greater than 128 bits and is a function of `NrLanes` and the per-lane register file depth.
</Note>

## Target use cases

- **Academic research** — Ara is actively used in publications on vector processor microarchitecture, memory system design, and RISC-V ISA research. All hardware sources and benchmarks are openly available for reproduction and extension.
- **Hardware/software co-design** — The included application suite (matrix multiply, convolution, FFT, DWT, pathfinder, and more) and the Spike ISA simulator allow algorithm developers to profile and tune software before committing to silicon.
- **Custom SoC accelerators** — Ara's modular AXI4 interface and configurable lane count make it suitable as a vector acceleration block in custom chip designs targeting edge AI, signal processing, or scientific computing.
- **FPGA prototyping** — The Cheshire-based FPGA flow enables full-system prototyping on VCU128 and VCU118, including a Linux boot and RVV-accelerated userspace applications.

## Performance

Ara was taped out and characterized in **22 nm FD-SOI** technology, achieving a clock frequency of **1 GHz+** at nominal operating conditions (as reported in the IEEE TVLSI 2020 paper). The theoretical peak throughput scales linearly with lane count:

- Maximum throughput: **2 × NrLanes** 64-bit data packets per cycle
- A 4-lane configuration sustains up to 8 double-precision FLOP/cycle at 1 GHz
- A 16-lane configuration can sustain 32 FLOP/cycle at peak

Published results across three peer-reviewed papers cover single-core efficiency on matrix multiply, FFT, and convolution kernels; multi-core scalability (Ara2); and instruction-level benchmarking via `rvv-bench`.

<Note>
  Achievable throughput depends heavily on memory bandwidth, vectorization quality, and the ratio of compute to load/store instructions in the workload. The ideal dispatcher mode (replacing CVA6 with a FIFO) can be used to measure the upper-bound vector throughput independent of scalar dispatch overhead.
</Note>
